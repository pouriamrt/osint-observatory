## Exploring the workspace

Ctrl/Cmd+K searches modules and saved findings. Search inputs and completed results remain in browser memory while switching modules; a page reload clears unsaved research. Watchtower events and Hawk coordinates open radius-filtered camera views. Crypto graph nodes open a connection inspector before explicitly expanding history. Skywave supports sample scrubbing and pointer readings. The evidence notebook has module filters, sorting, and notes.

### Public camera directory

`server/sources/camera-catalog.json` contains a dated snapshot from the [EarthCam public map](https://www.earthcam.com/mapsearch/) and [SkylineWebcams public featured directory](https://www.skylinewebcams.com/en/webcam.html). EarthCam metadata can be refreshed from the map toolbar; an unavailable provider retains cached records.

Skyline pages do not publish the camera GPS position. Curated depicted places are linked to [Wikipedia GeoData coordinates](https://www.mediawiki.org/wiki/Extension:GeoData) and labeled approximate in the map inspector. Unmatched views are omitted rather than assigned invented locations. The snapshot includes source and attribution records. To rebuild it from these public sources, run `node scripts/build-camera-catalog.mjs`.

Provider preview images appear inside the workbench. Live playback opens at the provider because Skyline pages block third-party framing. Add other camera pages with the inline Add camera flow; unknown pages require user-supplied coordinates. Direct media can be imported for playback and detection when CORS allows it. Favorites persist locally and are included in workspace exports. Country selection focuses the map; the Canada shortcut clears conflicting filters. Place links such as `#camera?country=Canada&place=Ottawa` also survive reload. The bundled directory includes 2,708 Canadian entries across DriveBC, Québec, Toronto, Calgary, Ottawa, and EarthCam. `node scripts/canada-ui.mjs` checks country filtering, source links, and mobile marker visibility after a production build.

### Canadian public cameras

The original EarthCam snapshot only contained five Canadian views at three locations. Canadian coverage now also includes [DriveBC highway cameras](https://catalogue.data.gov.bc.ca/dataset/bc-highwaycams), [Québec transport cameras](https://www.donneesquebec.ca/recherche/dataset/camera-de-circulation), [Toronto traffic cameras](https://open.toronto.ca/dataset/traffic-cameras/), [Calgary traffic cameras](https://data.calgary.ca/Transportation-Transit/Traffic-Cameras/k7p9-kppz), and [Ottawa traffic cameras](https://traffic.ottawa.ca/en/opendata). Each record keeps the publisher's coordinates, source link, attribution, licence, and retrieval time. The current additional snapshot has 1,043 DriveBC, 680 Québec, 336 Toronto, 216 Calgary, and 428 Ottawa entries (399 municipal and 29 MTO cameras).

These additions primarily show periodic still images. The inspector refreshes selected snapshots automatically (Ottawa every five seconds, other sources every sixty seconds), with pause/resume controls and manual refresh. Updates stop while the tab is hidden or the camera is closed. The last successful image stays visible while its replacement loads or if a refresh fails. The displayed time is the fetch time, not the camera capture time; delayed DriveBC images are marked. Québec image links use the open GeoJSON camera codes and the image directories published on the official mobile camera pages. Its image host can reject third-party requests; a styled unavailable state keeps the official camera-page link accessible. A successful image load does not imply that the publisher has captured a new frame. Browser image analysis requires CORS, and is not enabled for these government snapshots. Ottawa snapshots use the image route and `timems` refresh parameter of the city's public traffic map. The city states that actual frames may stay the same for 5–15 seconds; this is a sequence of stills, not continuous video. Ottawa images preserve the city or MTO operator credit, and may display a provider outage card. Ottawa coordinates identify the mapped intersection or roadway location. The separate Ottawa open-data image API still requires a certificate. This is regional coverage, not an exhaustive Canada-wide inventory. Ontario 511's provincial API and Alberta 511 need developer keys; this build does not bypass those requirements.

Canadian metadata is cached separately by source and refreshed after 24 hours or via the camera refresh control. Failed sources retain their last metadata while other providers can refresh. To rebuild the bundled snapshot, run `node scripts/build-canadian-catalog.mjs`. The file is only replaced when every source succeeds. Open-data attribution appears in the inspector and source list and remains in evidence exports.

Camera Globe uses a full-width map above the camera list and a wide selected-camera viewer, following the same layout as Satellite views. On smaller screens the viewer and list stack below the map. The full source image fits inside the frame without cropping. **Expand view** opens camera previews full screen on either page, with refresh and pause controls still available; **Exit full screen** or Escape returns to the page.

The filtered camera list remains available alongside the selected view. Previous/next follows the list order, and Select camera reaches every matching entry without paging through thumbnails. Crowded markers on the globe or map expose a nearby group; Show all matching cameras returns to the full filtered list. City searches focus the flat map on the matching coverage. Toolbar Refresh immediately reloads the selected image and list thumbnails while refreshing directory metadata independently. Loaded frames remain visible during image requests and failures, and paused automatic updates stay paused.

City searches open the flat map automatically. Continued globe zoom switches to the detailed map, which supports zoom to individual intersections and displays camera names at close range. Clicking a numbered marker opens a searchable camera chooser directly on the map. Recognized Ottawa municipal and MTO outage cards are identified from the provider image bytes through a local image route; the provider's HTTP 200 outage cards are shown as offline, with a nearby-camera action. Camera lists and map choices identify cameras whose loaded images report an outage. All published cameras remain browsable, including offline ones.

The flat map shows OpenStreetMap roads, street names, and landmarks beneath camera pins, with visible map attribution. Roads and pins use the same Web Mercator projection. Scroll zoom stays anchored at the cursor; dragging, named cluster choices, the globe, and fullscreen remain available. Map tiles require internet access. A failed tile request shows a retry action while camera selection stays usable. No map API key is needed for the default street layer.

`npm run test:map-markers:ui` checks pointer-down, keyboard focus, cluster selection, phone layouts, and satellite/street marker rendering against synthetic fixtures while the development app is running. Focus uses small rings with non-scaling borders instead of the browser's SVG outline, which can grow with map zoom.

### Satellite views

Open **Satellite views** in the navigation for detailed Earth imagery and ISS live video. Enter a city, street, address, or `latitude, longitude`, then choose a search result. Ottawa, Toronto, and Tehran shortcuts focus the map without a provider search. Controls sit above the map; **About imagery** explains the source. **Satellite** is also available on Camera Globe and Watchtower maps, preserving the camera and event markers. All layers use the street map's Web Mercator projection and request only visible tiles.

- **Streets & buildings** is the default. Esri satellite/aerial photographs show streets, intersections, and buildings where coverage is available. **Street names** adds an optional road-label overlay. **Borders & city names**, enabled by default, adds country and province/state boundaries, including Canadian provinces and territories, plus city/town names at closer zoom. It is independent of street labels. City names do not represent municipal boundary polygons. Failed boundary requests show a retry action while imagery remains usable. Capture dates and resolution vary; these photographs are not live video. Address search uses Esri for temporary map navigation, and results are not saved to SQLite. Coordinate navigation works without a search provider.
- **Recent global imagery** shows NOAA-20 VIIRS daylight observations for a UTC day. Choose a historical date or use **Follow latest imagery**. New observations arrive within hours; clouds, night, incomplete daily coverage, and archive gaps can leave areas blank.
- **Weather · Americas** (GOES-East) and **Weather · Pacific** (GOES-West) show weather imagery roughly ten minutes apart, with processing delay. The observation time comes from NASA. Areas outside the supported tile coverage show a coverage message. Weather zoom stops at the provider's native resolution; switch to **Streets & buildings** for a closer view.
- The app checks NASA metadata every five minutes while a weather layer is active and visible. Pause/resume controls affect automatic updates; manual refresh remains available. Choosing a historical UTC date stops following the latest day. Failed refreshes retain previously loaded tiles with a warning; switching source or observation time clears old imagery.
- **Camera pins** show public cameras near your chosen place. Adjust the nearby radius, filter view types, search the camera list, or click a pin. Featured Times Square, Abbey Road, and Bourbon Street views use official EarthCam YouTube players. Nearby Canadian road cameras generally provide refreshed snapshots, labeled separately from video. Imported HLS streams and video files also work here; their live status is not independently verified. Provider-only records link to the original camera website. Stop video unloads its player.
- The app checks the official EarthCam channel and NASA station playlist every five minutes while the page is visible, following replacement stream IDs. Live status is dated; an unsuccessful check shows status unverified, and a missing current broadcast shows off air. Provider playback restrictions and delays can vary.
- **Satellite video clips** includes Planet’s recorded SkySat footage of Dubai airport, published in 2017. It is labeled recorded, with a source link and no invented capture date. Commercial satellite video captures short clips during a pass and requires provider access; these public sources do not offer continuous live video of a selected street.
- **ISS live video** offers NASA's exterior Earth camera and station/mission-audio stream. Select a camera, load the player, and press play. Stop video unloads the player; reload reconnects it. Playback uses YouTube with origin-only referrer information. Live/recorded status is reported by the provider's player, and NASA may substitute recordings or show signal-loss screens. If the embed is blocked or the stream moves, open the stream or NASA's current station playlist. The camera follows the station's orbit and cannot be aimed at your chosen map location.

The default public endpoints currently work without provider credentials. Detailed imagery: [Esri World Imagery](https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer). Weather imagery: [NASA GIBS documentation](https://nasa-gibs.github.io/gibs-api-docs/). Video: [NASA Live](https://www.nasa.gov/live/), [official NASA station streams](https://www.youtube.com/playlist?list=PL2aBZuCeDwlQMf6xMgQAUAY_nbHAgW5jz).

Only tiles intersecting the settled viewport are requested; browser caching is preserved and there is no offline download or prefetch feature. Street tile images send the app origin as their Referer, overriding the app's no-referrer policy for those images only, in accordance with the [OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/). An alternative raster provider can be configured with `VITE_MAP_TILE_URL` (containing `{z}`, `{x}`, `{y}`, with zoom levels 0–19), `VITE_MAP_ATTRIBUTION_TEXT`, and `VITE_MAP_ATTRIBUTION_URL` in `.env`. Restart Vite or rebuild after changing these values. Set the attribution required by the chosen provider.

With the app running, `npm run test:streets:ui` checks tile/pin alignment, cursor zoom, pan, camera choices, tile outages and retry, desktop/tablet/mobile, and fullscreen. Automated map gestures use local synthetic tile fixtures to avoid requests to public tile servers.

With the app running, `node scripts/camera-city-ui.mjs` repeats the globe-zoom, on-map camera selection, real MTO outage, nearby switching, and actual municipal-image checks. `node scripts/ottawa-availability-probe.mjs` checks every published Ottawa image and writes a dated availability report under `artifacts/`; availability can change between checks.

### Live radio in Skywave

Skywave opens in **Live audio** mode with Ottawa, Ontario selected. Choose **EMS & OPP (Ottawa & Region)**, then **Listen on Broadcastify**. The official provider player opens in a new tab; sign in with a free Broadcastify account, then press Play there. Broadcastify reports current availability, controls any introductory advertising, and determines broadcast delay. This listing identifies provincial police and EMS in the region; it does not advertise Ottawa Police Service dispatch. Aviation and amateur-radio links are included separately.

Public feed links use the provider's own player rather than republishing its streams or scraping a live catalogue. Broadcastify's [current developer policy](https://support.broadcastify.com/hc/en-us/articles/204740425-Live-Audio-Feed-Catalog-API) does not license new scanner applications wrapping its live audio. The [Ottawa feed directory](https://www.broadcastify.com/listen/ctid/4311) remains the source for current local availability.

**Nearby frequencies** lists published frequencies around Ottawa, rather than signals detected from your computer or GPS location. It defaults to **Has online audio**, so users without a receiver can open an aviation feed, the VE3OCE amateur-repeater feed, or CKCU’s station website. Search by MHz, callsign, location, or service. Choose **All listed frequencies** to include OARC’s VE2CRA VHF/UHF repeaters, marked **Receiver needed** because this directory has no verified browser audio link for them. The displayed repeater frequencies are receive frequencies, rather than repeater inputs. Each entry links its source and the source-check date.

Airport frequencies 122.700, 122.800, and 123.500 MHz open one [shared airport feed](https://www.broadcastify.com/listen/feed/47740); VE3OCE 146.880 and 443.800 MHz open one [shared VHF/UHF feed](https://www.broadcastify.com/listen/feed/47504). Selecting an entry does not select an individual channel within those provider feeds. Availability and delay belong to the provider. CKCU’s [official website](https://www.ckcufm.com/) has a **Listen Live** control for 93.1 FM programming. [OARC equipment details](https://oarc.net/equipment/) identify its local repeater frequencies. A scanner or SDR and antenna are needed to receive local signals without an online source; this version does not tune receiver hardware or scan the RF spectrum.

For a public or personally operated direct audio source, paste its HTTP/HTTPS URL into **Play a direct audio stream here**, optionally name it, and choose **Connect & listen**. Native browser audio supports compatible MP3, AAC, Ogg, and other audio formats. HLS is supported when the browser or stream permits it. Use the native controls to pause, resume, or adjust volume; **Reconnect audio** retries a dropped feed, and **Stop audio** releases the player. Switching to spectrum captures or another module also stops in-app audio. A source URL or successful playback does not independently prove that a recording is live. These audio URLs stay in the current view and are not saved to the evidence database.

**Live transcript & AI analysis** captures audio from a browser tab you explicitly select. In desktop Chrome or Edge, play the authorized radio feed, click **Start tab capture**, select its tab, enable **Share tab audio**, and press **Share**. The source label is supplied by you; the application does not independently verify which service is speaking. Select 10-, 15-, or 30-second transcript updates and a 1-, 5-, or 10-minute session limit. Each finished clip is sent to OpenAI for transcription; this is near-live chunked processing, not instantaneous captions. Quiet clips below the audio-level threshold are skipped; this is not speech detection. API usage charges apply. **Stop capture**, changing Skywave modes, or leaving the module releases capture tracks and cancels queued/in-flight transcription requests. Unfinished clips are discarded on Stop.

Audio is converted to mono 16 kHz PCM and processed by the server using the configured OpenAI key. The key is never sent to the frontend. Video frames from the browser’s sharing API are discarded. Capture does not scrape the Broadcastify website, extract private media URLs, or supply account credentials. [Broadcastify’s current terms, section 9](https://www.broadcastify.com/terms/) require separate permission for automated capture and AI processing, including transcription and summaries; a listening/Premium account alone does not grant it. Use licensed feed audio or another source you are authorized to process.

The transcript shows clip times, speaker turns when provided by the transcription model, replayable audio, audio level in dBFS, and optional comma-separated keyword matches. Speaker labels reset within each clip and do not identify a person. dBFS is recorded-audio level, not RF power in dBm. Radio static and overlapping transmissions can cause transcription errors; check names, addresses and numbers against the clip. **Analyze audio file** accepts a browser-decodable clip up to 8 MB and 60 seconds.

**Ask AI about the transcript** summarizes or answers a question using the latest available transcript window. Mentions include exact quotes and references to supporting clips; mentions that cannot be matched to the transcript are removed. These are unverified interpretations of machine transcripts, rather than confirmed incidents, diagnoses or speaker identities. Raw audio and results stay in this view, with a 40-clip limit. **Export transcript** downloads transcript JSON; **Save evidence** explicitly saves a selected transcript or analysis to the local notebook without raw audio. Leaving the view or **Clear session** releases audio clips.

Location mentions in the AI analysis have a **Cameras nearby** button. It looks up the quoted place using the existing Esri search, with Ottawa as an editable search hint. Check the place match against the supporting clip, choose a 10–100 km radius, then select a match to open **Satellite views & nearby cameras** in a new tab. Satellite views focuses on the place, keeps the chosen radius, and opens the closest available camera in its larger player. Switching nearby cameras retains the original location as the distance origin. Each match also has an **Open Camera Globe directory** link. The radio session stays available in the original tab. Coordinates come from place search, not from the AI; matches are temporary navigation data and are not saved with the analysis. Results show public cameras in the directory, whose positions and image availability depend on their providers.

`npm run test:radio:analysis:ui` checks user-initiated tab capture, real AudioWorklet PCM chunks, silence gating, replay, speaker turns, keyword matches, summary references, location-to-camera navigation and radius filtering, explicit evidence saving, export, cancellation/cleanup, outages and responsive layouts with controlled synthetic fixtures. API calls in this suite are stubbed and incur no OpenAI usage charges.

**Spectrum captures** retains the existing import, frequency filters, sample slider, power plot, waterfall, and evidence saving. Its values remain imported instrument measurements in Hz/dBm; listening to audio does not fabricate RF spectrum data.

`npm run test:radio:ui` checks provider destinations, frequency searches and filters, receiver-only/shared-feed labels, user-initiated audio, pause/resume, stop/cleanup, source switching, outages, HLS errors, spectrum controls, and mobile layouts using synthetic audio and RF fixtures in an isolated workspace.

## Configure providers

Copy `.env.example` to `.env` and set optional values. Restart the server after changes. No key is required for basic public-data and import workflows.

- `OPENAI_API_KEY`: server-side OpenAI access for radio transcription and on-demand AI summaries. The key must stay out of frontend code. API usage charges apply.
- `RADIO_TRANSCRIBE_MODEL`: defaults to `gpt-4o-transcribe-diarize` for clip-local speaker turns.
- `RADIO_SUMMARY_MODEL`: defaults to `gpt-4.1-mini` for transcript analysis with structured output.
- `GITHUB_TOKEN`: increases GitHub public API quota.
- `HIBP_API_KEY`: licensed Have I Been Pwned account-breach endpoint.
- `BLOCKSCOUT_API_KEY`: Blockscout PRO native EVM transaction lookup using `chain_id`; chain support depends on your provider.
- `SCAN_ALLOWLIST`: exact literal IPs, domains, .onion hosts, or IPv4 CIDRs you are permitted to test. Loopback is the default. CIDR input ranges are limited to `/28`–`/32`. A domain resolving to a private address requires that address to be explicitly allowlisted too.
- `TOR_HOST` / `TOR_PORT`: running local Tor SOCKS5 proxy. The application does not install or start Tor.
- `PORT`: API / production frontend port, default 8787. If changed in development, also update Vite's API proxy.
- `DB_PATH`: optional database filename.

The application intentionally binds to localhost and rejects nonlocal Host/Origin headers. It has no multiuser login or internet deployment configuration. Keep this binding for local use. Remote deployment would require authentication, TLS, access control, retention settings, and a deliberate visitor-sharing design.

## Imports

Each module has an import panel and downloadable CSV header template. Use CSV or a JSON array (or `{ "rows": [...] }`). Up to 50,000 rows / 18 MB per file. Imports validate atomically; exact duplicate normalized rows are skipped. Use ISO 8601 timestamps with a timezone, decimal-degree coordinates, and HTTP(S) source URLs without embedded credentials.

- Cameras: `name,lat,lon,url,source,kind,country`; kind is `image`, `video`, `hls`, or `page`.
- Transfers: `chain,hash,from,to,amount,asset,timestamp,source,url`; URL optional; `amount` is a nonnegative decimal string. Failed transactions should not be exported as transfers. Give chain a consistent identifier such as `bitcoin` or `ethereum`.
- Spectrum: `frequency_hz,dbm,timestamp,source`.
- Events: `title,lat,lon,category,source,url,timestamp,magnitude`; URL/magnitude optional. Point GeoJSON with these properties is also supported.
- Registry sources: `name,jurisdiction,category,url,access`; `access` defaults to manual. Use `{q}` in a source URL to substitute a search query. Imported source URLs remain manual leads; API labels do not enable arbitrary automatic querying.
- Registry records: `title,identifier,source,url,jurisdiction,timestamp`; URL/jurisdiction/timestamp optional; JSON may also include a `details` object.

No sample records are presented as real observations. The test suite uses clearly identified synthetic fixtures in an in-memory database.

## Data and sources

Data is stored in `data/workbench.sqlite`; the app never sends your evidence notebook or images to an AI service. Provider searches send the query to the selected provider. External media and links connect directly to their hosts. Imported data and saved evidence remain on this machine until you export them.

Provider documentation: [USGS](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php), [NASA EONET](https://eonet.gsfc.nasa.gov/docs/v3), [NOAA SWPC](https://www.swpc.noaa.gov/), [mempool.space](https://mempool.space/docs/api/rest), [Blockscout PRO](https://docs.blockscout.com/devs/pro-api), [GitHub](https://docs.github.com/en/rest/users/users), [Hacker News](https://github.com/HackerNews/API), [GitLab](https://docs.gitlab.com/api/users/), [GLEIF](https://www.gleif.org/en/lei-data/gleif-api), [HIBP](https://haveibeenpwned.com/API/v3), [TensorFlow COCO-SSD](https://github.com/tensorflow/tfjs-models/tree/master/coco-ssd).

Geographic boundary asset: Natural Earth-derived low-resolution country polygons rendered from the local GeoJSON. Boundaries are cartographic context and not a position on sovereignty. Fonts are self-hosted DM Sans and IBM Plex Mono.
